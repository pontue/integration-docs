OAuth

Operações de autenticação via OAuth

Obtém um token de acesso

Obtém um token de acesso para fazer o login de um usuário.

IMPORTANTE:
Caso for fazer o Login SSO, insira a seguinte informação no campo scope: login-sso.
Se não for fazer o Login SSO, não envie o campo scope.

Para o Login SSO, redirecionar o usuário para a URL: https://sso.dev.pontue.com.br com os seguintes parâmetros na query string: ssoAccessToken (access_token recebido nesse endpoint) e uma das três opções id (ID do usuário na nossa plataforma) ou idRef (ID de referência do usuário) ou email (e-mail do usuário).

Request Body schema: multipart/form-data
grant_type
required
string
Default: "client_credentials"

O tipo de concessão da solicitação de token (Utilize: client_credentials).

client_id
required
string

ID fornecido pela nossa equipe de TI.

client_secret
required
string

Token fornecido pela nossa equipe de TI.

scope
string

Escopo da solicitação de token. Todos os escopos disponíveis são separados por espaço.
Caso for fazer o Login SSO, insira login-sso, caso contrário, não envie esse campo.

Responses

https://api.dev.pontue.com.br/oauth/token

Response samples

  • 200
  • 401
Content type
application/json
{
  • "token_type": "string",
  • "expires_in": 0,
  • "access_token": "string"
}

Obter token de acesso de usuário

Obtém dados de acesso do usuário.

IMPORTANTE:
No Header Authorization, utilizar o token_type + access_token retornado pelo endpoint /oauth/token.
Exemplo: Authorization: Bearer eyJ0eXAiOiJ....
Porém, aqui na documentação, adicione apenas o access_token, pois o token_type é adicionado automaticamente.

Proposal

Operações de propostas

Criação de proposta

OBS: Utilize o access_token retornado pelo endpoint /oauth/token para autenticação.

Authorizations:
Authorization
Request Body schema: multipart/form-data
name
required
string

O nome da proposta.

gridId
required
string <uuid>

ID da grade da proposta.

mockExam[name]
required
string

Identificador do simulado. Não é exibido diretamente; serve para identificar as propostas que pertencem a um mesmo simulado.

subjectId
string <uuid>

O ID da disciplina (caso a proposta seja disponibilizada para uma disciplina).

Exclusivo com schoolClasses: se subjectId for enviado, o campo schoolClasses é ignorado.

schoolClasses[]
Array of strings <uuid> [ items <uuid > ]

IDs das turmas para as quais a proposta será disponibilizada.

Exclusivo com subjectId: só é considerado quando subjectId não for enviado.

Exemplo:
schoolClasses[]: 9b1d...
schoolClasses[]: 7c2e...

hasTask
boolean
Default: false

Indica se a proposta possui tarefa ou não.

allowSecondView
boolean
Default: false

Indica se é permitido solicitar segunda vista (revisão) da correção.

mockExam[isFaceToFace]
boolean
Default: false

Indica se o simulado é presencial (true) ou online (false).
Quando true, os campos mockExam[startDate] e mockExam[endDate] são ignorados.

mockExam[startDate]
string <date-time>

Data de início do simulado online, no formato YYYY-MM-DD HH:mm:ss.
Considerado apenas quando mockExam[isFaceToFace] for false.

mockExam[endDate]
string <date-time>

Data de término do simulado online, no formato YYYY-MM-DD HH:mm:ss.
Considerado apenas quando mockExam[isFaceToFace] for false.

mockExam[allowCorrectionView]
boolean
Default: false

Indica se o aluno pode visualizar a correção da redação do simulado.

file_labels[]
Array of strings

Labels dos arquivos.
Campo obrigatório se enviado arquivos.

Cada item deve ser uma string JSON (e não um objeto) com os atributos:
id: ID do arquivo (explicado no atributo file-1).
label: Título do arquivo que será apresentado ao usuário.
name: O nome do arquivo que o usuário fez o upload.

Exemplo:
file_labels[]: {"id":"1","label":"Texto motivador","name":"texto.pdf"}
file-1: (arquivo binário)

file-1
string <binary>

Arquivo para a proposta.

Campo obrigatório se não enviado links.
Formatos permitidos: pdf, jpg, jpeg e png.

O 1 descrito no final do nome deste campo é o ID do arquivo especificado no campo file_labels.

Exemplo:
Com file_labels[0] contendo "id":"nomeDoArquivo1", o arquivo deve ser enviado com o seguinte nome do campo: file-nomeDoArquivo1.
Com file_labels[1] contendo "id":"nomeDoArquivo2", o arquivo deve ser enviado com o seguinte nome do campo: file-nomeDoArquivo2.

file-2
string <binary>

Arquivo para a proposta.

Campo obrigatório se não enviado links.
Formatos permitidos: pdf, jpg, jpeg e png.

O 2 descrito no final do nome deste campo é o ID do arquivo especificado no campo file_labels.

Exemplo:
Com file_labels[0] contendo "id":"nomeDoArquivo1", o arquivo deve ser enviado com o seguinte nome do campo: file-nomeDoArquivo1.
Com file_labels[1] contendo "id":"nomeDoArquivo2", o arquivo deve ser enviado com o seguinte nome do campo: file-nomeDoArquivo2.

links[]
Array of strings

Links para a proposta.
Campo obrigatório se não enviado arquivos.

Cada item deve ser uma string JSON (e não um objeto) com os atributos:
url: URL do link.
label: Título do link que será apresentado ao usuário.

Exemplo:
links[]: {"url":"https://exemplo.com/texto","label":"Texto de apoio"}

Liberar propostas

Libera a proposta para uma disciplina ou para turmas e ajusta as configurações de liberação.
OBS: Somente os campos enviados são alterados. Campos não enviados mantêm o valor atual.
OBS: Se enviados subjectId e schoolClasses, será dada preferência para a disciplina.
OBS: Utilize o access_token retornado pelo endpoint /oauth/token para autenticação.

Authorizations:
Authorization
path Parameters
proposalId
required
string <uuid>

ID da proposta.

Request Body schema: application/json
subjectId
string <uuid>

ID da disciplina para a qual a proposta será liberada.

Exclusivo com schoolClasses: se subjectId for enviado, o campo schoolClasses é ignorado e a proposta deixa de estar vinculada às turmas anteriores.

Array of objects

Turmas para as quais a proposta será liberada.

Substitui a lista atual: as turmas já vinculadas que não forem enviadas serão desvinculadas da proposta.
Só é considerado quando subjectId não for enviado.

releaseAt
string or null

Data em que a proposta deve ser liberada.
Formato: DD/MM/YYYY HH:mm:ss (Ex.: 23/09/2022 08:00:00)

Campo não enviado: mantém a data atual.
null ou vazio: remove a data de liberação.
Preenchido: define a nova data de liberação.

removeAt
string or null

Data em que a proposta deve ser removida.
Formato: DD/MM/YYYY HH:mm:ss (Ex.: 30/09/2022 23:59:59)
Deve ser posterior à data de liberação.

Campo não enviado: mantém a data atual.
null ou vazio: remove a data de remoção.
Preenchido: define a nova data de remoção.

allowSecondView
boolean

Indica se é permitido solicitar segunda vista (revisão) da correção.
Campo não enviado: mantém o valor atual.

allowCorrectionView
boolean

Indica se o aluno pode visualizar a correção da redação do simulado.
Campo não enviado: mantém o valor atual.

Responses

https://api.dev.pontue.com.br/integrations/proposal/{proposalId}/makeAvailable

Request samples

  • Payload
Content type
application/json
{
  • "subjectId": "68460e63-0717-47f9-8fd8-d28f152cb30b",
  • "schoolClasses": [
    • {
      • "id": "497f6eca-6276-4993-bfeb-53cbbbba6f08"
      }
    ],
  • "releaseAt": "23/09/2022 08:00:00",
  • "removeAt": "30/09/2022 23:59:59",
  • "allowSecondView": true,
  • "allowCorrectionView": true
}

  • 401
  • 404
Content type

  • "message": "string"
